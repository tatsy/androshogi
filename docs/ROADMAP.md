### 定跡ファイルの読み込み（2026-10-07 検討メモ）

自分のオンライン対局の検討、プロ棋譜・定跡書の棋譜並べを主な用途とする。
現在局面に登録された候補手と評価値を、通常のエンジン検討とは別に参照できるようにする。
[KifMaster](https://kifmaster.com/) のような定跡の反復練習は参考にするが、練習モードは初期の読み込み機能とは分けて検討する。

- [ ] やねうら王のテキスト定跡形式（`#YANEURAOU-DB2016 1.00`、`.db`）の読み込みに対応する
  - `.db` は SQLite やハッシュファイルではなく、SFEN と指し手・評価値などを並べたテキスト
  - 登録手をすべて推奨手として扱わず、候補手と評価値を確認できる表示を検討する
  - データには通常、手の狙いを説明する文章や戦型名がない。解説・戦型分類は別機能とする
- [ ] ユーザーが選択した定跡ファイルを取り込む方法を検討する
  - 下表の小さな定跡から試し、同じ形式の新ペタショック定跡へも拡張できるようにする
  - アプリ同梱の要否は未決定。同梱する場合は、その配布データ自体のライセンス・表記を確認する
- [ ] 局面検索の方式を比較し、初回読み込み時間・検索時間・使用メモリを実機で確認する
  - 有力案は、初回に SFEN → ファイル内の位置の索引を作り、該当局面の候補手だけ読む方式
  - 全件をメモリ上のハッシュ表に保持する方式、ソート済みファイルを二分探索する方式も比較対象
  - 取り込み・索引作成はバックグラウンドで行い、局面ごとにファイル全体を走査しない
  - 手数を除いた SFEN（盤面・持ち駒・手番）による照合と、先後反転局面の扱いを検討する

容量は2026-10-07に公式配布ファイルを確認した値（MB は十進、展開後は定跡本体のみ）。
100T／700T は生成時に探索した局面数であり、収録局面数ではない。

### 戦型入力・自動判定（2026-10-07 検討メモ）

戦型を棋譜情報として保存し、後で「四間飛車だけ見直す」などの整理・検索につなげる。
完全な自動分類を目指さず、手動入力を基本として、自動入力を補助機能にする。

合意した画面・保存仕様：

- [ ] 既存のプレイヤー名編集ダイアログを「棋譜情報の編集」に拡張する
  - 先手名・後手名に加えて、自由入力の「戦型」欄と「自動入力」ボタンを用意する
  - 例：`角換わり`、`先手四間飛車／後手居飛車`、`先手矢倉／後手雁木`
  - 判定できた場合だけ戦型欄を書き換える。判定できない場合は既存入力を残し、欄の下に手動入力を促す表示を出す
  - `未判定` という文字を戦型欄に自動入力しない。追加の通知ダイアログは設けない
  - 「保存」で名前と戦型を反映し、「キャンセル」では自動入力結果も破棄する
- [ ] 戦型を内部の自動保存データに保持し、KIF の `戦型：…` として入出力する
  - 空欄なら戦型ヘッダーは出力しない。読み込んだ戦型・手動入力を、自動入力ボタンの操作なしに上書きしない
  - アプリ内の戦型による絞り込みは別途検討する。KIF 出力だけでは内部の検索機能にはならない

自動判定・辞書の初期実装案（詳細条件・精度は未検証）：

- 対象は振り飛車の大分類（向かい飛車・三間飛車・四間飛車・中飛車）と、相居飛車の角換わり・横歩取り・矢倉・雁木・相掛かり
- 矢倉・雁木などは、必要なマスだけを指定した駒配置の部分一致で候補を検出する
  - 小さな JSON 辞書を `app/src/main/assets/opening_patterns.json` に同梱する案
  - 戦型 ID・表示名・複数の配置パターンを持ち、指定マスはすべて一致、パターン間は OR とする
  - 後手は盤面・駒の所属を反転して先手用の条件を再利用する。辞書の外部編集・取り込みは初期対象外
- 角換わり・横歩取り・相掛かりは、角交換・飛車先の歩交換・横歩取りなどの履歴を判定コードで確認する
  - 相掛かりでの後の角交換を角換わりと誤判定しない。他の戦型に該当しないことだけで相掛かりに分類しない
- 序盤の局面を再生して照合する。最大60手程度を初期案とするが、上限は代表棋譜で調整する
  - 現在局面だけで判断せず、成立した戦型を記録する。途中の仮の形・組み替え・先後で異なる戦型を扱う
  - 本譜と選択分岐のどちらを判定対象にするかは、KIF の出力対象との整合を含め実装時に決める
- 曖昧な場合は未判定とし、手動修正できるようにする。腰掛け銀・棒銀・青野流などの細分類、学習モデル、曖昧一致の点数制は初期対象外
- 代表棋譜、手順前後、戦型の組み替え、紛らわしい棋譜で判定精度を確認し、必要なパターンだけ追加する

参考：[Lichess のオープニング辞書](https://github.com/lichess-org/chess-openings)は、
名前付き局面との完全一致を行い、棋譜中の最後の一致を分類に用いる方式を推奨している。
辞書と処理の分離、序盤全体の照合、判定結果の保持を参考にする。
完全一致は端歩などの違いに弱いため、将棋の大分類では部分一致・着手履歴を基本とし、
名前付き SFEN の完全一致辞書は将来の細分類向けに検討する。
